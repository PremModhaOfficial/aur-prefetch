# Frozen rubric

Five checks per metric, weights **3 / 2 / 2 / 2 / 1** (sum 10). Score is the sum
of passed weights. A metric passes the hillclimb target at **≥ 9**, which means
every 3- and 2-point check passes; only the 1-point polish check may fail.
The implementation is [`evaluate.mjs`](evaluate.mjs). Do not edit it between
iterations; that is what "frozen" means.

| Metric | w3 core | w2 | w2 | w2 | w1 polish |
|---|---|---|---|---|---|
| HIE | Dashboard starts with a verdict (summary, drift, next action) | Every screen starts with a verdict/summary | One primary action per screen, or read-only | Partial-upgrade state on the drift line and dashboard | Help teaches download/install and partial-upgrade risk |
| DEN | Updates has package/repo/installed/available/size/cached | Inspector holds detail, not the row | Dashboard shows disk/inodes/timer/lock/trust/caches | Caches and activity use four-column tables | Settings shows setting/value/source |

## Why this metric

The user asked for **9 or above on every metric**. A single 0–10 judgment per
metric is not checkable, so each metric is decomposed into evidence the spec and
prototype either contain or do not. The 3/2/2/2/1 shape makes the target
unambiguous: a 9 requires the complete substantive story, not a lucky average.

## Limits

- This is a design-completeness rubric, not user testing.
- Checks read a design model (`design.json`), not production code. Atlas is a
  target, not a shipped TUI.
- The baseline and each after-score are in [`RESULTS.md`](RESULTS.md); the raw
  log is `decision.tsv` (gitignored, regenerated by `node iterate.mjs`).
